# OPPLE-FE6300
Base on ESP-8266

### Build
```sh
pio run -e opple-fe6300
```

### Upload
遥控指令（`variant/.default/data/opple-fe6300.json`）在文件系统镜像里，不在固件里。
首次烧录，或修改了指令文件后，需要先上传文件系统，再上传固件：

```sh
pio run -e opple-fe6300 -t uploadfs
pio run -e opple-fe6300 -t upload
```

只上传固件时，串口会提示 `no commands loaded`，发送会返回 `unknown command`。

### 遥控协议（由 `docs/saleae` 抓包得出）

原遥控器只发不收：每按一次键，在信道 74（2476 MHz）上把同一个 19 字节的包连发约 12 次，每次间隔约 13 ms。本机发送次数和间隔分别由配置中的 `burstCount` 和 `burstPeriodMs` 控制。

| 字节 | 示例 | 含义 |
| :--: | :--: | :-- |
| 0..3 | `A3 71 4D 01` | 遥控器地址（另一个遥控器为 `A3 BF 57 01`） |
| 10..11 | `00 38` | 按键计数，16 位大端，每按一次 +1，同一次按键的重复包相同 |
| 15 | `37` | 键码：`37` 照明（开关切换）、`50` 关机（关掉当前模式，不影响照明）、`3F` 取暖、`3B` 吹风、`90` 干燥、`39` 换气、`5A` 沐浴；`4D` 见下 |

所有按键都是切换键，开和关是同一个包，只是计数不同。照明独立；取暖、吹风、干燥、换气、沐浴是互斥的模式，同一时间最多开一个；关机关掉当前模式，不影响照明。`opple-fe6300.json` 的 `packet` 节点保存报文字段，顺序与包里的字节一致；字节位置只在 `lib/OppleFE6300/OppleFE6300Packet.h` 里定义，发送时按字段拼包，接收时把包拆回字段：

| 配置项 | 字节 | 值 |
| :-- | :--: | :-- |
| `packet.remote` | 0..3 | 本机遥控器地址；换去控制另一台浴霸只改这里（如 `A3BF5701`） |
| `packet.prefix` | 4..7 | `00000000`，固定 |
| `packet.length` | 8..9 | `0013`，固定（= 19，可能是长度） |
| `packet.sequence` | 10..11 | 按键计数，默认 `0000`，作为初始基准；上电后第一次本机发送使用其 +1，之后每次新指令 +1。听到同地址原遥控器后，下一条本机指令使用其计数 + `sequenceGap`（默认 100 十进制，如 `00BB` → `011F`；负数表示计数回退），之后每次 +1；`FFFF` 后回绕到 `0000`。配置文件不会回写 |
| `packet.padding` | 12..13 | `0000`，固定 |
| `packet.type` | 14 | `03`，固定 |
| `packet.keys` | 15 | 各键键码，如 `{ "light": "37", "powerOff": "50", ... }` |
| `packet.postfix` | 16..18 | `005701`，固定 |
| `burstCount` | — | 每条指令重复发送次数，范围 `1`..`255`，默认 `15` |
| `burstPeriodMs` | — | 突发中每个包的最小发送起始间隔，单位毫秒，范围 `0`..`255`，默认 `13` |
| `sequenceGap` | — | 收到同地址原遥控器计数后，本机下一条指令采用的有符号 16 位计数偏移（`-32768`..`32767`），默认 `100`；负数会使计数回退；之后每条指令 +1 |

快速连按时遥控器的两个行为（实测）：

- 连按照明约每 4 下，有 1 下发出的键码是 `4D` 而不是 `37`。浴霸收到 `4D` 不做任何动作，所以照明少翻转一次；状态推算同样忽略它，日志里显示为 `unknown`。
- 计数有时会跳号而空中没有信号（trace 里那段 RSSI 为 0），浴霸也收不到这些按键，所以这种 `sequence skipped` 不影响推算的状态。

### 接收原遥控器

LT8920 在两次发送之间处于接收状态，配置与遥控器相同（信道、同步字、包格式），只是关掉 AUTO_ACK，只听不答。收到的包拆成字段后，固定字段（`prefix`、`length`、`padding`、`type`、`postfix`）与 `opple-fe6300.json` 一致才算遥控器的包，再按键码查出命令名，地址和计数不参与识别，所以任何遥控器的按键都能识别；同一次按键的重复包只报告一次。只有本机遥控器的按键会改变推算的状态；其他遥控器（如 `A3BF5701`）控制的是另一台浴霸，只记录不计入。

每个遥控器的计数分别记录，计数跳号时打印 `sequence skipped`（附带当时的错误计数）：多数是遥控器快速连按时自己跳号，空中没有信号，浴霸也收不到；少数是本机没收到，这时推算的状态可能不准，可以看 trace 区分。超过 50 ms 没收到包就重新进入接收，防止芯片卡在某个状态收不到信号（一次按键约 170 ms、约 50 个包，所以即使卡住也还能收到后半段）。

跳号后，等接收端安静约 300 ms（期间没再收到包）再打印 `[trace]`，免得几十行输出阻塞串口、耽误接收；连续几次跳号合并成一份，从最早那次的上一次按键开始：接收端每一段经历（`rx 计数 xN` 收到的包、`crc`/`empty`/`oversize`、`rearm xN stuck M` 空闲重新接收）及该段空闲时采样到的最高 RSSI。按键包之间的 RSSI 就是遥控器在空中的强度；如果跳号期间的 `rearm` 段 RSSI 同样高，说明遥控器在发而本机没收到（`stuck` > 0 表示芯片收到同步字却没收完包）；如果 RSSI 很低，说明那段时间空中没有信号，计数跳号来自遥控器本身。

本机每条新指令使用递增后的计数，同一突发内的重复包保持相同计数；`FFFF` 后回绕到 `0000`。收到同地址原遥控器的按键后，本机下一条指令使用该计数加有符号 `sequenceGap` 的结果，之后继续逐次递增，以调整两侧计数的位置。

上电时串口打印一次寄存器和收发计数（`[status]`）；遥控器按键会打印为 `[rx]`，包含地址、`counter` 和该按键前收到的副本数；同一次按键的重复包合并为一行。本机发送会打印 `[send]` 结果和 `counter`。推算的各功能状态打印为 `[state]`。浴霸不回报状态，所以状态是推算的：上电默认全关。之后每次按键（遥控器或本机）：照明键翻转照明；模式键在该模式已开时关掉它，否则打开它并关掉其他模式；关机关掉所有模式。

### LT8920 与 NodeMCU 接线图

NodeMCU 的引脚（D0-D8）与 ESP8266 的原生 GPIO 存在映射关系。以下是将 ESP-12F 引脚转换为 NodeMCU 标准引脚（D系列）后的完整接线指南。

| LT8920 引脚 | 信号类型 |  NodeMCU 引脚   | ESP8266 GPIO | 功能说明与接线逻辑                 |
| :-------: | :--: | :-----------: | :----------: | :------------------------ |
|  **GND**  | 电源地  | **GND (或 G)** |     GND      | 系统公共接地                    |
|  **VDD**  | 供电正极 |    **3V3**    |  VCC (3.3V)  | 必须接入稳定的 3.3V 供电，切勿接 5V    |
|  **CLK**  | 串行时钟 |    **D5**     |    GPIO14    | 硬件 HSPI 时钟输出引脚            |
| **MOSI**  | 主机输出 |    **D7**     |    GPIO13    | 硬件 HSPI 数据输出引脚            |
| **MISO**  | 主机输入 |    **D6**     |    GPIO12    | 硬件 HSPI 数据输入引脚            |
|  **CS**   | 片选使能 |    **D2**     |    GPIO4     | 软件片选控制线（避开 GPIO15）        |
|  **PKT**  | 收发状态 |    **D1**     |    GPIO5     | SDK 默认高有效；完成时拉高，接收中断使用上升沿 |
|  **RST**  | 芯片复位 |    **D0**     |    GPIO16    | 由 SDK 输出低电平复位脉冲，再拉高释放复位   |
